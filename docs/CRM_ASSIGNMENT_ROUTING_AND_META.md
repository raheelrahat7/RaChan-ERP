# CRM assignment routing and Meta Lead Ads intake

## Confirmed policy

Owners and Administrators can route leads by Meta form ID, exact Meta form name, connected Meta Page, exact campaign name, exact project name, and finally the existing stage default pool. This order is fixed. A more specific matching route that has no eligible agent holds the lead; it does not fall through to a broader pool. A route can target selected members, an active department, an active subdepartment, or an active team. The department hierarchy determines the eligible members. Existing assignees are preserved.

An agent is eligible only when they are a current organization member, checked in for the current date in the organization's configured IANA timezone, and below their owner-set active-lead quota. Active leads are currently assigned, unconverted leads in stages other than Won and Lost. A quota of zero disables new automatic assignments. The checked-in status expires on the next local date. There is no attendance system yet, so CRM daily check-in is the availability source. Routing uses a row lock to serialize selection and quota checks across simultaneous lead arrivals.

If no agent qualifies, the lead remains unassigned in the CRM assignment hold queue. Owners and Administrators receive one in-app notification per hold episode; agents do not receive hold notices. The queue retries in arrival order when an agent checks in or a quota/route changes, and once per minute via `crm:retry-held-leads`. Manual assignment resolves the hold. Won, Lost, and converted leads do not receive automatic assignments or continue waiting in the queue. Rule changes, quotas, check-in, holds, and automatic assignments are audited.

## Configure Meta Lead Ads

1. In the correct organization, open CRM → Assignment routing as an Owner or Administrator. Connect each Meta Page with its Page ID, Page access token, Meta app secret, webhook verify token and Graph API version. Select an optional destination department. One organization can connect multiple Pages; the same Page cannot be connected to another organization. Credentials are encrypted at rest and never rendered back into the page. Use **Edit** to change the department or Graph version later; blank secret fields keep their stored values. Replacing the Page token, app secret, or verify token clears the subscription indicator until **Subscribe leadgen** succeeds again.
2. Expose the app through a public HTTPS URL. Each connected Page displays a callback URL. For Pages using the same Meta app, configure one of those URLs and its verify token as that app's Page webhook callback. Pages in the same organization with the same app secret can share it. The callback verifies Meta's challenge and checks the SHA-256 signature on POST requests. Use **Subscribe leadgen** for every connected Page.
3. A Page with a destination department automatically creates a Page-specific routing rule. A form ID or form-name rule takes precedence; then the Page rule, followed by campaign, project and stage defaults. Eligible members come from active teams inside that department. Without a destination department, the other routing rules apply.
4. Run a Redis queue worker for imports, for example `php artisan queue:work redis --queue=default --tries=3`, and keep Laravel's scheduler running for held-lead retries. For the current local container, `sh scripts/start-local-crm-worker.sh` starts the worker in the background. `sh scripts/start-local-scheduler.sh` starts the scheduler. Re-run these after a container restart.
5. Submit a test lead with Meta's Lead Ads Testing Tool. The Page callback records the Meta lead ID once in the Page's organization, fetches the lead and form name from Graph API, and creates one CRM lead. It maps form fields by name, including first/last/full name, email, phone, company, and an optional `project` or `project_name`; it uses Meta's campaign name when provided. A submission without a name or contact still creates a clearly labeled `Meta Lead <ID>` record for later correction. Imports stay pending during queue retries; only final failures show a Retry action to Owners and Administrators. Repeated Retry clicks enqueue one job until that attempt finishes. Form ID routing works even when form-name lookup is unavailable.

The original shared-app callback `/webhooks/meta/leadgen` and `.env` settings remain available for previously connected Pages that have no Page-specific app secret. New customer setups should use each Page's private callback and credentials in CRM.

The signed webhook and Graph responses are covered with local fakes. A live Meta connection still requires the organization's real Meta app, Page token, public HTTPS callback, and Meta permissions. The endpoint and payload shape follow [Meta's Lead Ads webhook sample](https://github.com/fbsamples/lead-ads-webhook-sample/blob/main/postman/FB%20Lead%20Ads%20%28Part%201%20-%20The%20Webhook%29.postman_collection.json); the lead fields follow [Meta's Business SDK Lead object](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/lead.py).
