## Basis and counting

This is a source-and-document audit, not production certification. It compares the 15 numbered sections in [PRODUCT_COMPLETION_PLAN.md](PRODUCT_COMPLETION_PLAN.md) with routes, domain models/actions, pages, migrations and focused tests in this repository. **Implemented locally** means the named section has a substantial working slice and tests; it does not mean owner or regulatory acceptance. **Partial** means some named capabilities exist but the full section is not delivered. **Missing** means no dedicated workflow for the section's main capabilities was found. A broader code, data, security and usability review is still required before a live release.

The master plan has seven phases (0–6). Foundation and identity are implemented locally; phases 2–6 contain active work or acceptance gaps. Across the product-completion workstreams below, **2 sections are implemented locally, 9 are partial, and 4 are missing**. Thus 13 of 15 still require implementation to meet the _full_ roadmap, and all 15 require a release decision or acceptance before claiming the complete product.

## Recommended first-release boundary

For a first organization pilot, retain the already-built identity, CRM Kanban/list and routing, inventory, basic listings, reservations/leases, invoicing and AED ledger, manual bank reconciliation, maintenance, private documents and notifications. Put VAT/corporate-tax filing claims, live provider connections and optional AMC/construction/fleet/SSO features outside the pilot unless explicitly selected and validated. The user approved this boundary on 2026-09-21; see [PILOT_RELEASE_SCOPE_2026_09_21.md](PILOT_RELEASE_SCOPE_2026_09_21.md) for its explicit inclusions, exclusions and release gates.

The next work should be ordered as follows:

1. **Agree the pilot scope and users.** Confirm whether live Meta import, accounting/tax, Ejari/PDC and customer-facing access must be in the first release. This determines which partial sections are actual blockers.
2. **Close workflow acceptance.** Run the CRM owner/phone walkthrough in [CRM_ACCEPTANCE_REVIEW_2026_09_20.md](CRM_ACCEPTANCE_REVIEW_2026_09_20.md) and the leasing/finance scenarios in [LEASING_ACCEPTANCE_CHECKLIST.md](LEASING_ACCEPTANCE_CHECKLIST.md). Record pass/fail and resolve failures.
3. **Validate promised external behavior.** Connect real Meta Pages only when credentials and a public HTTPS callback are available; use a test lead per Page. Obtain accountant/regulatory sign-off before treating tax reports as compliant filings.
4. **Prepare production operations.** Choose hosting/domain, managed MySQL/Redis, mail and private storage; set up deployment, backups and restore drills, queue/error monitoring, tenant-isolation review and a release rehearsal using [DEPLOYMENT_READINESS.md](DEPLOYMENT_READINESS.md).
5. **Build only the pilot gaps.** Prioritize missing workflows within the agreed boundary. The automated lead → reservation/lease → invoice/payment → bank/ledger → maintenance journey now passes; repeat it in a human release rehearsal before launch.
