# Property & Listings Phase 2A backend contract

The existing `status` remains the operational state (`draft`, `active`, `paused`, `closed`). Only operational `active` listings are public and eligible for inquiries, matches and transaction links. `workflow_status` is a separate organization-editable display strip. Its values never publish a listing or change a financial/portal record. Listings created before this field existed are returned and filtered as workflow `draft` until explicitly moved.

## Listing records

- `POST /real-estate/listings` retains the current form body: `inventory_mode` (`existing_unit` or `new_unit`), existing-unit `unit_id` or the established new-unit/property/building fields, required `purpose` (`sale|rent`) and nonnegative `price`; optional `broker_id`, `market_segment` and Phase 2A fields below. HTML form posts redirect as before. JSON posts return `201 {"listing":{"id":19,"version":1,"reference":"LST-...","status":"draft","workflow_status":"documents_pending","price":"1200000.00","price_per_sqft":"1000.00","permissions":{"read":true,"edit":true,"change_status":true},...}}`.
- `GET /real-estate/listings/data` accepts optional `market_segment=primary|secondary`, `status=draft|active|paused|closed`, `workflow_status`, `listing_category`, `broker_id`, `cost_centre_id`, `emirate`, `community`, `q`, `sort=latest|price_asc|price_desc`, `page`. Response: `{"listings":{"data":[{"id":19,"version":1,"unit":{"number":"1204"},"property":{"name":"Marina"},"building":null,"price_per_sqft":"1000.00","permissions":{"read":true,"edit":true,"change_status":true},...}],"current_page":1,...},"workflowStatuses":[{"code":"draft","name":"Draft","position":0,"active":true,"id":null,"version":null},...],"emirateSummary":[{"emirate":"Dubai","total":1}],"filters":{},"permissions":{"read":true,"create":true,"configure":true}}`. Pagination is 50 records. `GET /real-estate/listings/{listing}` returns `{listing, workflowStatuses}` with the same listing shape. Both are organization-scoped. The existing Inertia `/real-estate/listings` and `/real-estate/secondary-market` pages also receive `workflowStatuses`, `emirateSummary`, `filters`, `owners`, `costCentres` and serialized listings.
- `PUT /real-estate/listings/{listing}` requires `expected_version` and accepts any subset of the Phase 2A fields. Example `{"expected_version":1,"workflow_status":"documents_pending","emirate":"Dubai","community":"Marina","size_sqft":"1200.00","dld_permit":"DLD-1"}`. Response `200 {"listing":{"id":19,"version":2,"price_per_sqft":"1000.00","permissions":{"read":true,"edit":true,"change_status":true},...}}`.

Optional Phase 2A fields: `workflow_status`, `cost_centre_id`, `owner_id`, `listing_category`, `unit_category`, `emirate`, `community`, `sub_community`, `trakheesi_permit`, `dld_permit`, `bedroom_type`, `bedrooms`, `bathrooms`, `balconies`, `parking_spaces`, `size_sqft`, `plot_size_sqft`, `furnishing`, `completion_status`, `handover_date` (`YYYY-MM-DD`), `grade`, `loading_bay` (boolean), `fit_out`, `price_type`, `price_min`, `price_max`, `price_label`, `developer_name`, `portals` (array of unique strings), `price`, `currency` (three uppercase letters), and `broker_id`. The existing create body already covers property/building/unit/floor. `price_per_sqft` is computed from `price / size_sqft` (or the linked unit's area when it is in square feet) and is read-only. Nullable fields can be cleared with `null`. `price_min <= price_max` when both are set. `cost_centre_id`, `owner_id` and `broker_id` must belong to the current organization.

The existing `PUT /real-estate/listings/{listing}/status` body remains `{"status":"active"}`; it now also accepts `expected_version` and increments `version`. The existing `PUT /real-estate/listings/{listing}/market-segment` body remains `{"market_segment":"secondary"}` and likewise accepts `expected_version`. The version key is optional on these two legacy routes until their current frontend callers send it; new detail updates require it.

## Organization workflow statuses

Defaults are 13 editable codes: `draft`, `documents_pending`, `verification`, `approval_pending`, `approved`, `ready_to_publish`, `published`, `active`, `on_hold`, `under_offer`, `sold`, `rented`, `withdrawn`. They are returned without database IDs until first configuration write. `POST /real-estate/listings/workflow-statuses` body `{"code":"legal_review","name":"Legal Review","position":14,"active":true}` creates a status; posting an untouched default code customizes that default once (response version 2), after which updates use its ID and version. New status response: `201 {"workflowStatus":{"id":14,"code":"legal_review","name":"Legal Review","position":14,"active":true,"version":1}}`. `PUT /real-estate/listings/workflow-statuses/{status}` requires `{"code":"legal_review","name":"Legal Check","position":14,"active":true,"expected_version":1}`; response `200 {"workflowStatus":{..."version":2}}`. Codes cannot change after creation. Inactive codes remain on historical listings but cannot be selected for new edits.

Listing reads require `viewCrm`; creates, detail edits, operational status changes and workflow-status configuration require `manageCrm`. The `permissions` object reflects these checks. Foreign organization records return 404; unauthorized writes return 403. Validation and stale versions return Laravel JSON `422 {"message":"...","errors":{"expected_version":["..."],"workflow_status":["..."]}}` with the relevant field key. Examples include invalid date, negative size/price, unknown status, cross-organization owner/cost centre/broker, price range order, and stale `expected_version`.
