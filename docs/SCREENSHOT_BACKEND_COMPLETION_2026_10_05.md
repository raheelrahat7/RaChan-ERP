## HTTP contracts

All endpoints require authenticated, verified organization members; configuration writes require owner/admin settings authority. Read responses apply current permissions.

| Method       | Path                                                         | Contract                                                                                                                                                                                                                                                      |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET/PUT      | `/crm/settings/calendar`                                     | `working_days` keyed by ISO weekday, each `{start,end}` in `H:i`; `holidays` ISO dates. Organization timezone applies.                                                                                                                                        |
| PUT          | `/crm/deals/{deal}/financial-links`                          | `kind` invoice/commission, `record_id`, `expected_version`, optional `remove`.                                                                                                                                                                                |
| GET/POST/PUT | `/organization/reference-settings/{kind}[/{record}]`         | Kinds `currencies`, `locations`, `numbering`, `providers`. GET `{records,kind,providerCapabilities,deliveryEnabled}`; writes return `{id}`.                                                                                                                   |
| POST         | `/organization/reference-settings/currencies/rebase`         | `base_code`, complete `rates` array of `{code,exchange_rate,face_value}`.                                                                                                                                                                                     |
| POST         | `/organization/provider-packets`                             | `profile_id`, UUID `operation_key`, capability-specific `payload`; returns local validation/hash/packet/ID with `deliveryEnabled:false`. No network delivery.                                                                                                 |
| GET/POST     | `/reference-workflows`                                       | GET filters `kind,pipeline_id,stage_id,q,page`; returns accessible pipelines, paginated records, matching stage counts and configuration metadata. POST `pipeline_id,title,assigned_to,details,operation_key` and applicable related IDs; returns `{record}`. |
| GET/PUT      | `/reference-workflows/{record}`                              | GET record/history/permissions/linked invoice summary. PUT title/assignee/details/expected_version; related record links are immutable.                                                                                                                       |
| PUT          | `/reference-workflows/{record}/stage`                        | `stage_id,expected_version`, optional reason; transfers also supply `pipeline_id,confirmed:true`.                                                                                                                                                             |
| POST         | `/reference-workflows/{record}/invoice`                      | Accepted estimate ID, `expected_version,due_on,accounting_treatment`, VAT treatment when enabled; returns `{invoice}`.                                                                                                                                        |
| POST/PUT     | `/reference-workflows/pipelines[/{pipeline}]`                | `kind,name,active,position,read_roles,edit_roles,field_definitions`. Kind is immutable.                                                                                                                                                                       |
| POST/PUT     | `/reference-workflows/pipelines/{pipeline}/stages[/{stage}]` | `name,type,color,position,active,is_initial,entry_roles,allowed_from_stage_ids,required_fields,source_statuses`.                                                                                                                                              |

Deal pipeline writes additionally accept `lead_field_mapping` (`deal_key:lead_key`); deal stage writes accept `financial_requirement`. Deal lists/exports accept `custom_filters:[{field,operator,value}]`, with `filterFields` supplying supported operators. Deal automation writes additionally accept `conditions`, `working_hours_only` and `target_stage_id` for `change_stage`.

Workflow field definitions use `{key,name,type,required,options?}` with types `text,number,date,checkbox,select`. Values belong in `details.custom_fields`; stage requirements use `custom:key`. Used field keys/types cannot be removed/changed, while labels, requirements and choices remain editable. Built-in estimate details are `currency,lines,valid_until,notes`; recruitment details include candidate/job/contact/resume/offer/interview/joining data. Resume and offer references point to externally managed evidence; this tracker does not create staff employment records or upload recruitment attachments. Document progress does not prove a legal signature. Existing private document versioning and retention remain authoritative.
