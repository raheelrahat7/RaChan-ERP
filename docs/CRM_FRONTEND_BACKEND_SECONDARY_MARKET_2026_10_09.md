# Secondary Market Phase 2B backend contract

Phase 2B extends the existing listing record. `owner_id` is the seller (an organization-owned Owner); `buyer_contact_id` is the buyer (an organization-owned CRM Contact). These fields track the secondary-market file and do not create a reservation, contract, invoice, or accounting posting. Operational `status` still controls listing availability; the configurable `workflow_status` supplies the secondary-market status tabs.

| Route | Request | Response |
| --- | --- | --- |
| `POST /real-estate/listings` | Existing create body, with `purpose: "sale", market_segment: "secondary"` (or `purpose: "rent"`). Optional `owner_id`, `buyer_contact_id`, `valuation_price`, `mortgage_status`, `noc_status`, `transfer_status`. | JSON `201 {"listing":{"id":19,"version":1,"market_segment":"secondary","valuation_price":"950000.00","seller":{"id":4,"name":"Seller A","phone":null,"email":null},"buyer":{"id":8,"first_name":"Buyer","last_name":"B","phone":null,"email":null},"permissions":{"read":true,"edit":true,"change_status":true},...}}`; HTML posts redirect. |
| `GET /real-estate/listings/data?market_segment=secondary` | Existing listing filters, including `workflow_status` for the selected tab, and `page`. | `200 {"listings":{"data":[{"id":19,"version":1,"mortgage_status":"preapproved","noc_status":"pending","transfer_status":"awaiting_documents","permissions":{"read":true,"edit":true,"change_status":true},...}],"current_page":1,...},"workflowStatuses":[{"code":"draft","name":"Draft","position":0,"active":true,"id":null,"version":null},...],"secondaryStatusSummary":[{"code":"draft","total":3}],"emirateSummary":[],"filters":{"market_segment":"secondary"},"permissions":{"read":true,"create":true,"configure":true}}`. The summary ignores the selected `workflow_status` but respects the other filters. |
| `GET /real-estate/listings/{listing}` | No body. | `200 {"listing":{...same fields and permissions...},"workflowStatuses":[...]}`. |
| `PUT /real-estate/listings/{listing}` | Required `expected_version`; optional subset of secondary fields and Phase 2A listing fields. Example `{"expected_version":1,"valuation_price":"975000.00","noc_status":"issued","transfer_status":"scheduled","buyer_contact_id":8}`. Explicit `null` clears a secondary field. | `200 {"listing":{"id":19,"version":2,"valuation_price":"975000.00","noc_status":"issued","transfer_status":"scheduled","buyer_contact_id":8,"permissions":{"read":true,"edit":true,"change_status":true},...}}`. |
| `GET /real-estate/secondary-market` | Optional listing filters, including `workflow_status` for a tab. | Existing Inertia `real-estate/Listings` props now include `secondaryStatusSummary` and `buyerContacts`, alongside `workflowStatuses`, `owners`, `listings`, `filters` and existing props. |

`valuation_price` is a nonnegative decimal with two fractional digits in responses. The three status strings are optional organization-defined labels (up to 60 characters); the listing `workflow_status` options are configured with the existing `POST/PUT /real-estate/listings/workflow-statuses` routes documented in `CRM_FRONTEND_BACKEND_LISTINGS_2026_10_09.md`. The status summary counts only secondary listings, including rentals. Seller and buyer links are validated against the current organization. The list is paged at 50 records.

Reads require `viewCrm`. Create and update require `manageCrm`; their serialized `permissions` show `read`, `edit` and `change_status`. Foreign organization listings return 404, unauthorized writes 403. Validation returns Laravel JSON `422 {"message":"...","errors":{"field":["..."]}}`; field keys include `expected_version` for missing/stale versions, `valuation_price` for invalid/primary-only values, `buyer_contact_id` or `owner_id` for cross-organization records, and status fields for invalid values. Creates include `version: 1`; every update requires `expected_version` and returns the incremented `version`.
