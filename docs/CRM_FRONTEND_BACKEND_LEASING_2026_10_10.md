# Phase 2C Leasing & Rental backend contract

The existing lease, Ejari, deposit, cheque, and handover workflows remain authoritative. `tenancy_number`, `renewal_due_on`, and `advance_amount` are lease tracking fields. `advance_amount` records the agreed advance; it does **not** create an invoice, payment or journal. Security deposit amounts come from `lease_security_deposits`, Ejari numbers from registered `lease_ejari_registrations`, and cheque rows from `lease_cheques`; the lease API does not duplicate them.

The lease's operational `status` remains `draft`, `active`, or `completed`. `renewal_due` is computed for an active lease when `renewal_due_on` (or `ends_on` when unset) is within 60 days. The `renewed` tab means an active lease with a recorded `last_renewed_on` that is not currently renewal-due. The `moved_out` tab requires a completed move-out handover; it follows the existing handover workflow. A completed handover increments the lease version. The `move_out` object contains `id`, `status`, `scheduled_on`, and `completed_at`.

Existing action routes remain the write paths for linked records: `POST /lease-compliance/leases/{lease}/security-deposit` (`amount`, `due_on`, optional `notes`), `POST /lease-compliance/leases/{lease}/cheques` (`cheque_number`, `bank_name`, `payer_name`, `amount`, `due_on`, optional `replacement_of_id`), `POST /lease-compliance/leases/{lease}/ejari` (`applied_on`, optional `notes`), and `POST /handovers` (`lease_id`, `type:"move_out"`, optional `scheduled_on`, `notes`). Those existing routes return redirects and retain their established permissions and financial safeguards. `POST /handovers/{handover}/complete` completes the move-out and opens a vacancy through the existing workflow. No new direct "move out" or payment shortcut is introduced.

Reads require `viewTransactions`; creates, detail edits, renewals, and linked actions require `manageTransactions` (with any stricter existing deposit/finance checks still applying). Every lease serializer includes `permissions`. Foreign organization leases return 404 and unauthorized writes 403. Validation and stale-version failures are Laravel JSON `422 {"message":"...","errors":{"field":["..."]}}`, including keys such as `expected_version`, `tenancy_number`, `renewal_due_on`, `advance_amount`, `ends_on`, or `status`. The tenancy number must be unique within the organization. New JSON lease creates include `version:1`; new detail updates and JSON renewals require `expected_version` and return the incremented version.
